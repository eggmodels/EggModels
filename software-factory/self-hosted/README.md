# Self-hosted factory runtime

This directory turns the software factory (see `../README.md` and `../BACKLOG.md`,
added in PR #51) into something that runs entirely on infrastructure Eugenio owns,
instead of depending on any hosted proprietary agent or on his own machine staying on.

## Architecture

```
┌─────────────────────────── your VPS ───────────────────────────┐
│                                                                  │
│  GitHub Actions self-hosted runner  (official, open source)     │
│     registers to eggmodels/EggModels, runs the repo's            │
│     existing workflows (CI, factory-auto-merge.yml) on your      │
│     own compute instead of GitHub-hosted runners                │
│                                                                  │
│  cron ── weekly ──▶ run-factory.sh                               │
│                        │                                         │
│                        ▼                                         │
│                 reads software-factory/BACKLOG.md                │
│                        │                                         │
│                        ▼                                         │
│                 aider (open source, MIT)  ──▶ edits + commits    │
│                        │                                         │
│                        ▼                                         │
│                 git push + `gh pr create --label factory-automated` │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘
                              │
                              ▼
                 GitHub (repo/PR host, unchanged) ──▶ factory-auto-merge.yml
                 auto-merges once CI is green, unless the diff touches
                 functions/**, .github/workflows/**, firestore.rules,
                 database.rules.json, firebase.json, .firebaserc
```

Nothing here depends on this Claude project thread, a laptop, or a hosted agent
product. The queue (`BACKLOG.md`), the policy (`README.md`,
`factory-auto-merge.yml`), and now the compute (this VPS) all live under
Eugenio's control.

## What you need

- A small VPS you control (any provider). 2-4GB RAM is enough to run the runner
  and `aider` sequentially (they're not resource-heavy; aider's cost is mostly
  API calls, not local compute). Rough cost: Hetzner CX22 ~€4.5/mo, DigitalOcean
  basic droplet ~$6/mo.
- An Anthropic (or OpenAI) API key of your own, used only by `aider` on this box,
  billed to your account. Typical usage for one small weekly PR: a few dollars/month.
  (A fully local model via Ollama is possible instead — needs a much bigger box
  and gives weaker results; see the tradeoff note below.)
- A GitHub personal access token (or fine-grained token scoped to this repo) for
  `gh` to open PRs from the VPS, and a runner registration token (Settings →
  Actions → Runners → New self-hosted runner) to attach the Actions runner —
  both one-time, generated by you, never pass through this project's sandbox.
- "Allow auto-merge" turned on in Settings → General (outstanding from PR #51).

## Setup (run as a non-root user on the VPS)

```bash
# 1. Actions runner (compute for CI + factory-auto-merge.yml)
./setup-runner.sh <registration-token-from-github-settings>

# 2. aider + gh CLI
./setup-aider.sh

# 3. put your own LLM key where only this box can read it
echo 'export ANTHROPIC_API_KEY=sk-ant-...' >> ~/.factory-env
chmod 600 ~/.factory-env

# 4. schedule the weekly run (replace the path if you cloned elsewhere)
crontab -e
# add:
# 0 14 * * 1  . /home/youruser/.factory-env && /path/to/run-factory.sh >> /var/log/factory.log 2>&1
```

`run-factory.sh` is capped at one PR per run, same as the existing Claude-driven
trigger, so the two can coexist or you can disable the Claude trigger once this
is confirmed working.

## Local-model alternative

If "own my data" means code should never leave your box at all, swap aider's
backend for a local model served by Ollama on the same VPS instead of an
Anthropic/OpenAI API key. It removes the external API dependency entirely, but
needs a much bigger box (16GB+ RAM) and gives noticeably weaker results on real
coding tasks than a frontier model. Not set up by default here; ask if you want
this instead.

## Why Aider instead of OpenHands

An earlier attempt to run OpenHands (Agent Canvas) in a local VM failed on
dependency issues. Aider is a single pip-installable CLI built specifically for
unattended "point it at a repo and a task, let it edit and commit" use — far
less to go wrong on a headless box with no display, and far fewer moving parts
than OpenHands' server + UI stack.
