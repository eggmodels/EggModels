# Self-hosted factory runtime

This directory turns the software factory (see `../README.md` and `../BACKLOG.md`,
added in PR #51) into something that runs entirely on infrastructure Eugenio owns,
instead of depending on his own machine staying on.

## Architecture

```
┌─────────────────────────── your VPS ───────────────────────────┐
│                                                                  │
│  GitHub Actions self-hosted runner  (official, open source)     │
│     registers to eggmodels/EggModels, runs the repo's            │
│     existing workflows (CI, factory-auto-merge.yml) on your      │
│     own compute instead of GitHub-hosted runners                │
│                                                                  │
│  cron ── weekly ──▶ run-factory.sh                               │
│                        │                                         │
│                        ▼                                         │
│                 reads software-factory/BACKLOG.md                │
│                        │                                         │
│                        ▼                                         │
│         claude -p  (headless, your Claude subscription)          │
│              or  aider (open source, your API key)                │
│                        │         ──▶ edits + commits             │
│                        ▼                                         │
│                 git push + `gh pr create --label factory-automated` │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘
                              │
                              ▼
                 GitHub (repo/PR host, unchanged) ──▶ factory-auto-merge.yml
                 auto-merges once CI is green, unless the diff touches
                 functions/**, .github/workflows/**, firestore.rules,
                 database.rules.json, firebase.json, .firebaserc
```

Nothing here depends on this Claude project thread or a laptop staying on. The
queue (`BACKLOG.md`), the policy (`README.md`, `factory-auto-merge.yml`), and
the compute (this VPS) all live under Eugenio's control.

## Implementer: Claude Code (default) vs Aider

**`claude-code` (default)** runs headless Claude Code (`claude -p`) on your
VPS, authenticated with `CLAUDE_CODE_OAUTH_TOKEN` — a long-lived (1 year)
token from `claude setup-token`, which uses your existing Claude subscription
(Pro/Max/Team/Enterprise) instead of a separate pay-per-token API key. No
extra billing beyond your subscription; usage counts against that plan's
usage limits, same as any other Claude Code session — if the factory's weekly
run is heavy relative to your plan, it can compete with your own interactive
usage or get throttled until the plan's window resets. `setup-token` requires
one interactive browser step (it does not persist the token itself), so you
run it by hand, once, on or from the VPS.

**`aider`** is the open-source alternative (kept from the original version of
this PR): a lighter CLI, billed per-token against your own Anthropic/OpenAI
API key. Useful if you'd rather keep the factory's usage completely separate
from your subscription's limits, or want a fully local model via Ollama (see
below).

Switch between them with `FACTORY_IMPLEMENTER=claude-code|aider` (see
`run-factory.sh`).

## What you need

- A small VPS you control (any provider). 2-4GB RAM is enough. Rough cost:
  Hetzner CX22 ~€4.5/mo, DigitalOcean basic droplet ~$6/mo.
- Either a Claude subscription (Pro or above) for the `claude-code` path, or
  your own Anthropic/OpenAI API key for the `aider` path.
- A GitHub personal access token (or fine-grained token scoped to this repo)
  for `gh` to open PRs from the VPS, and a runner registration token
  (Settings → Actions → Runners → New self-hosted runner) to attach the
  Actions runner — both one-time, generated by you, never pass through this
  project's sandbox.
- "Allow auto-merge" turned on in Settings → General (outstanding from PR #51).

## Setup (run as a non-root user on the VPS)

```bash
# 1. Actions runner (compute for CI + factory-auto-merge.yml)
./setup-runner.sh <registration-token-from-github-settings>

# 2a. Claude Code (default implementer, uses your subscription)
./setup-claude-code.sh
claude setup-token        # interactive, one-time; follow the printed instructions

# 2b. OR aider (alternative implementer, uses your own API key)
./setup-aider.sh
echo 'export ANTHROPIC_API_KEY=sk-ant-...' >> ~/.factory-env
chmod 600 ~/.factory-env

# 3. schedule the weekly run (replace the path if you cloned elsewhere)
crontab -e
# add:
# 0 14 * * 1  . /home/youruser/.factory-env && FACTORY_IMPLEMENTER=claude-code /path/to/run-factory.sh >> /var/log/factory.log 2>&1
```

`run-factory.sh` is capped at one PR per run, same as the existing Claude-driven
trigger, so the two can coexist or you can disable the Claude trigger once this
is confirmed working.

## Local-model alternative

If you'd rather code never leave your box at all, swap Aider's backend for a
local model served by Ollama on the same VPS instead of either the Claude
subscription or an API key. It removes any external dependency entirely, but
needs a much bigger box (16GB+ RAM) and gives noticeably weaker results on
real coding tasks. Not set up by default here; ask if you want this instead.

## Why headless Claude Code over OpenHands

An earlier attempt to run OpenHands (Agent Canvas) in a local VM failed on
dependency issues. Headless Claude Code and Aider are both single-binary/CLI
tools built for unattended "point it at a repo and a task, let it edit and
commit" use — far less to go wrong on a headless box with no display than
OpenHands' server + UI stack.
